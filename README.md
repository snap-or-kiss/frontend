# 빼빼로 데스매치 (Pepero Game)

AI와 빼빼로 한 개를 마주 먹는 고난이도 각도 맞추기 게임. 입술이 닿기 전에 최대한 많이 먹고, 점수(mm)로 경쟁한다.

- 플레이: https://snap-or-kiss.github.io/frontend/ (짧은 주소 https://snap-or-kiss.github.io/ 는 여기로 넘어간다)
- 저장소: https://github.com/snap-or-kiss/frontend (이 저장소). 백엔드는 `snap-or-kiss/backend`로 따로 만든다.
- 프런트엔드: 의존성 없는 단일 `index.html` (Canvas 2D + 바닐라 JS). 빌드 없음. 배포용 저장소는 따로 없다. 이 저장소의 `main`에 푸시하면 GitHub Pages가 바로 배포한다.
- 백엔드: 아직 없음. 친구가 개발한다. 이 문서의 [백엔드 명세](#b-백엔드)와 [CONTRACTS.md](CONTRACTS.md)가 합의 기준이다.
- 디자인: 리소그래프 × 멤피스. 어긋난 분홍·파랑 인쇄, 굵은 외곽선, 노란 스티커 라벨. 빼빼로만 입체적이다.

## 실행

```bash
python3 -m http.server 5173   # http://localhost:5173
node scripts/sim.js           # 헤드리스 시뮬레이션 검사
```

| 경로 | 내용 |
|---|---|
| `index.html` | 게임 전체 (스타일, 로직, 렌더링) |
| `scripts/sim.js` | 가짜 DOM에서 한 판을 돌려 규칙을 검사 |
| `scripts/scope-check.js` | PR이 `Scope:` 밖의 파일을 바꿨는지 경고 |
| `scripts/review-eval.sh` | 리뷰 지침이 심은 버그를 잡는지 평가 |
| `AGENTS.md`, `CLAUDE.md` | 에이전트 지침 |
| `CONVENTIONS.md` | 리뷰 체크리스트 |
| `CONTRACTS.md` | 프런트와 백엔드 사이 계약 등록부 |
| `docs/design-template.md` | 큰 변경 전 설계 문서 양식 |

## A. 프런트엔드

### A-1. 게임 규칙

| ID | 기능 | 명세 | 상태 |
|---|---|---|---|
| FE-01 | 판 흐름 | 시작 화면 → 플레이 → 결과 화면 → 다시 도전 또는 메뉴. 시작할 때 닉네임(최대 12자)을 저장한다. | ✅ |
| FE-02 | 빼빼로 | 길이 180mm = 660px. 왼쪽 끝은 내 입, 오른쪽 끝은 AI 입. 남은 길이 R은 두 입 사이 거리다. 손잡이(코팅 없는 비스킷)는 오른쪽 28%이며 모양일 뿐 판정과 무관하다. | ✅ |
| FE-03 | 조작 | 마우스 이동으로 입 방향을 정한다(입 중심에서 커서 방향). 클릭 유지 또는 Space 유지로 먹고, S 키 또는 화면 버튼으로 직접 끊는다. 모바일은 누른 채 드래그한다. 입과 커서가 50px보다 가까우면 각도를 바꾸지 않는다. | ✅ |
| FE-04 | 입 회전 | 최대 5rad/s로 제한되고 부드럽게 따라간다. 급한 조준은 늦는다. | ✅ |
| FE-05 | 각도 판정 | 오차 = 내 입 각도와 빼빼로 각도의 차(도). ≤ 9°이면 먹을 수 있다(TOL). ≤ 2.5°는 퍼펙트(PERFECT). 위쪽 게이지에 오차, 허용 구간(하늘색), 퍼펙트 구간(노랑)을 보여준다. | ✅ |
| FE-06 | 먹는 속도 | 14px/s(3.2mm/s) × q × (1 + 0.7 × FLOW). q는 퍼펙트이면 1, 허용 구간 끝에서 0까지 선형 감소. 허용 구간 밖은 0. | ✅ |
| FE-07 | FLOW(콤보) | 먹는 중 오차 ≤ 3.5°이면 초당 0.6씩 오른다(최대 1, 속도 ×1.7). 오차 > 5.4°이면 초당 1.5씩, 그 사이는 0.3씩 내려간다. 입을 떼면 초당 0.8씩 내려간다. | ✅ |
| FE-08 | 균열 | 먹는 중 오차 > 9°이면 초당 8 + (오차 − 9) × 7 증가. 5.85~9°는 초당 2 증가. 그보다 작으면 초당 5 감소. 입을 떼면 초당 16 감소. 100이 되면 부러진다. 70을 넘으면 화면이 떨리고, 올라갈수록 파란 인쇄판이 밀려난다. | ✅ |
| FE-09 | AI 움직임 | AI 입의 높이를 흔들어 빼빼로 각도를 바꾼다. 진폭 = min(26 + 1.6t, 100)px × 성격 계수(0.9/1/1.15). 3.4초에 처음, 이후 2.4~4.6초마다(갈수록 짧아짐) 급하게 꺾는다. 꺾기 0.45초 전에 눈이 깜빡이고 "!"가 뜬다. 남은 길이가 짧을수록 같은 흔들림이 큰 각도가 된다. | ✅ |
| FE-10 | AI 먹기 | 1.2초 뒤부터 먹는다. 성격별 기본 속도 7/9.5/12px/s에 0.55~1.35배(간헐적으로 +0.8배) 변동. | ✅ |
| FE-11 | AI 성격 | 판마다 무작위: 겁쟁이 30%, 신중 35%, 무모 35%. 눈 색으로 구분: 하늘색 / 노랑 / 빨강. 2초 뒤부터 겁쟁이는 남은 길이 46px(약 10.4mm), 신중은 22px(약 5mm) 이하에서 먼저 끊는다. 무모는 끊지 않는다. | ✅ |

### A-2. 종료와 점수

| 종료 | 조건 | 점수(mm) | 코인 |
|---|---|---|---|
| 내가 끊음(`snap`) | S 키 또는 버튼 | 먹은 길이. 남은 길이 ≤ 20mm이면 ×1.15 | 점수 반올림 |
| AI가 먼저 끊음(`aisnap`) | FE-11 조건 | 0 | 0 |
| 부러짐(`break`) | 균열 100 | 먹은 길이 × 0.5 | 점수 반올림 |
| 뽀뽀(`kiss`) | 남은 길이 ≤ 12px(약 2.7mm) | 0 | 0 |

- 점수는 소수 첫째 자리까지. 이론상 상한은 150 × 1.15 = 172.5mm.
- 종료 연출: 끊김과 부러짐은 빼빼로가 둘로 갈라지고, 뽀뽀는 하트가 터진다. 1.2초 뒤 결과 화면.
- 결과 화면: 제목, 점수, 이 기기 순위, 얻은 코인, 한 줄 해설.

## B. 백엔드

프런트는 정적 파일이라 백엔드는 API만 제공한다. 아래는 프런트가 기대하는 최소 명세이고, 합의되면 [CONTRACTS.md](CONTRACTS.md)에서 `agreed`로 올린다.

### B-1. API

| ID | 기능 | 명세 | 상태 |
|---|---|---|---|
| BE-01 | 점수 제출 | `POST /v1/scores`. 요청 본문은 아래 표. 성공하면 `201 {id, rank, score, name}`. | 🟡 |
| BE-02 | 순위 조회 | `GET /v1/leaderboard?limit=10&offset=0`. `limit` 기본 10, 최대 100. 응답 `{entries:[{rank,name,score,outcome,createdAt}], total}`. | 🟡 |
| BE-03 | 오류 형식 | 모든 오류는 `{error:{code,message}}`. `400` 검증 실패, `429` 제출 제한, `500` 서버 오류. `message`는 사용자에게 그대로 보여줄 수 있는 한국어 한 문장. | 🟡 |
| BE-04 | CORS | 허용: `https://snap-or-kiss.github.io`, 개발용 `http://localhost:5173`. 그 밖의 출처는 거부. | 🟡 |
| BE-05 | 저장 동기화(선택) | 코인과 보유 스킨을 계정에 묶는다. 로그인 방식이 정해지기 전에는 만들지 않는다. | 🟡 |

`POST /v1/scores` 요청 본문:

| 필드 | 타입 | 규칙 |
|---|---|---|
| `deviceId` | string(UUID) | 필수 |
| `name` | string | 필수. 앞뒤 공백을 자르고 1~12자 |
| `outcome` | `"snap"` \| `"break"` | 필수. `aisnap`, `kiss`는 0점이라 제출하지 않는다 |
| `eatenMm` | number | 필수. 0 초과 150 이하 |
| `remainingMm` | number | 필수. 0 이상 150 이하 |
| `durationMs` | integer | 필수. 판이 시작해서 끝날 때까지 |
| `score` | number | 필수. 서버가 다시 계산해서 다르면 거부 |
| `clientVersion` | string | 선택. 문제 추적용 |

### B-2. 검증과 순위

| ID | 기능 | 명세 | 상태 |
|---|---|---|---|
| BE-10 | 점수 재계산 | `snap`: `score = eatenMm × (remainingMm ≤ 20 ? 1.15 : 1)`. `break`: `score = eatenMm × 0.5`. 소수 첫째 자리 반올림. 요청 `score`와 0.1 넘게 다르면 `400`. | 🟡 |
| BE-11 | 범위 검사 | `score` ≤ 172.5(`snap`), ≤ 75(`break`). `eatenMm + remainingMm` ≤ 150. | 🟡 |
| BE-12 | 속도 검사 | 먹을 수 있는 최대 속도는 23.8px/s(= 14px/s × 1.7)다. `eatenMm / 0.2273`px를 그 속도로 먹는 데 걸리는 시간의 90% 미만인 `durationMs`는 거부한다. | 🟡 |
| BE-13 | 제출 제한 | 같은 `deviceId`는 10초에 1회, 같은 IP는 분당 60회. 넘으면 `429`와 `Retry-After`. | 🟡 |
| BE-14 | 닉네임 | 1~12자, 제어 문자 거부. 금칙어 목록은 설정 파일로 두고 걸리면 `400`. | 🟡 |
| BE-15 | 순위 정책 | 점수 내림차순, 같으면 먼저 제출한 순. 한 `deviceId`는 최고 기록 하나만 순위에 오른다. | 🟡 |
| BE-16 | 한계 | 위 검사는 조작을 어렵게 할 뿐 막지 못한다(클라이언트가 값을 보낸다). 제대로 막으려면 입력 기록을 서버가 재생해야 하고, 1차 범위에서는 하지 않는다. | 합의 필요 |

### B-3. 데이터와 운영

## 유의

"Pepero"는 롯데의 상표다. 서비스를 키울 때는 이름과 그래픽을 자체 브랜드로 바꾸는 것을 검토한다.

## 연속 플레이
남은 길이 20mm 이하에서 직접 끊으면 15% 보너스를 확보하고 1.2초 뒤 다음 빼빼로로 이어진다. 점수는 각 판 점수의 합이다. 실패한 판만 기존 규칙(균열 절반, AI 선제 종료·뽀뽀 0점)을 적용하며 이전 확보 점수는 보존한다. 두 번째 판부터 누적 점수를 확정하는 버튼을 제공한다. 진행 중인 판의 점수는 포기한다. 코인과 순위 등록은 전체 플레이가 끝날 때 한 번만 처리한다.

### 모드별 대시보드
기본 모드가 기본 선택이다. 한 개로 종료하며 기존 기록을 유지한다. 연속 모드는 별도 선택하며, 20mm 이하 직접 끊기 성공으로만 이어진다. 각 대시보드에 해당 모드 설명·최고 점수·순위를 표시한다. 연속 순위 저장 키는 pepero.lb.continuous.v1로 분리하며 코인과 스킨은 공유한다.

### 길이 조정
빼빼로를 180mm로 늘렸다. 화면에는 기존 크기에 맞춰 축소 표시하며, 양쪽 먹기 속도와 입술 접촉 거리는 실제 mm 기준으로 유지한다. 한 판 시간이 약 20% 늘어나고, 20mm 연속 성공 기준은 유지한다. 기존 기록은 보존하므로 이전 150mm 기록과 점수 조건은 다르다.
